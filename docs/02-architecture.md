# 2. 技術構成の提案

> 料金・無料枠は 2026年11月時点の把握です。変わることがあるので、契約前に各サービスの料金ページで確認してください。

## 結論

**Cloudflare Workers (画面と API を1つで配信) + Cloudflare D1 (データベース) + Cloudflare Access (ログイン) + GitHub (コード・自動デプロイ・自動バックアップ)**

```
 スマホ / PC のブラウザ ─┐
 Claude Code (cfm CLI) ─┼─▶ Cloudflare Access ─▶ Cloudflare Worker ─▶ D1 (データ)
 iPhone ショートカット ──┘    (本人確認)          ├ /       画面 (静的ファイル)
                                                  └ /api/*  API (検証・変更履歴)
 GitHub ─ Actions ─▶ テスト → バックアップ → マイグレーション → デプロイ
                   └▶ 毎日の暗号化バックアップ (90日保存)
```

## 比較

| | Cloudflare Workers + D1 (採用) | Cloudflare Pages + D1 | Supabase (無料) |
|---|---|---|---|
| 画面の配信 | 静的ファイルは無料・無制限 | 同左 | 別途ホスティングが必要 |
| API | Worker で実装 (1日10万リクエスト無料) | Pages Functions (中身は Workers と同じ) | 自動生成 API |
| DB | D1 (SQLite) 5GB 無料 | 同左 | PostgreSQL 500MB |
| 放置への強さ | 停止されない | 停止されない | **1週間アクセスが無いとプロジェクトが一時停止** |
| 自動バックアップ | Time Travel で巻き戻し (無料7日 / 有料30日) | 同左 | 無料枠にはバックアップ無し |
| ログイン | Cloudflare Access (50人まで無料) | 同左 | Supabase Auth |
| 将来性 | Cloudflare は新規開発を Workers に集約中 | 機能追加は Workers 側が先 | — |
| 1つの会社で完結 | ○ | ○ | DB と配信が別会社 |

**採用理由**
1. 個人の記録量 (1日数十件) なら D1 の無料枠 (5GB・1日10万行の書き込み) に何十年分も収まる。写真を1日1枚 (約300KB) 保存しても 5GB で約45年
2. Supabase の無料枠は「1週間使わないと停止」するため、怪我や旅行でしばらく記録しないと止まる。一生使う前提に合わない
3. 画面と API が同じドメイン・同じデプロイなので、構成が単純で壊れにくい
4. Cloudflare Access で、パスワードを自分で保管・管理せずにメール認証を付けられる (パスワード漏えいのリスクが無い)

## 無料でできる範囲と、お金がかかる範囲

| 項目 | 無料枠 | 想定使用量 | 有料になる条件 |
|---|---|---|---|
| Workers (API) | 1日10万リクエスト | 1日数百 | まず超えない |
| 静的ファイル配信 | 無制限 | — | — |
| D1 ストレージ | 5GB | 記録だけなら年数MB、写真込みで年100MB前後 | 写真を大量に保存する場合 → R2 へ (下記) |
| D1 読み取り / 書き込み | 1日500万行 / 10万行 | 1日数千 / 数十 | まず超えない |
| D1 Time Travel (巻き戻し) | 過去7日 | — | 30日にしたい場合は Workers 有料プラン (月$5) |
| Cloudflare Access | 50ユーザー | 1人 | — |
| GitHub Actions | public リポジトリは無制限 / private は月2,000分 | 1回3〜5分 × デプロイ数 + バックアップ毎日1〜2分 | private で毎日大量にデプロイする場合 |
| GitHub Artifacts (バックアップ保管) | public は無制限 / private は 500MB | 1回数MB × 90日 | 写真が増えて1回数十MBになった場合 |
| 独自ドメイン | — | 任意 | 取得するなら年1,500〜3,000円程度 (無くても `*.workers.dev` で使える) |
| Claude Code での分析 | 現在の Claude のプランの範囲 | — | アプリ内から Claude API を直接呼ぶ機能を作る場合は従量課金 (Anthropic API) |

**有料を検討するタイミング**
- 巻き戻し期間を30日にしたい → Workers Paid (月$5)。D1 の上限も大きくなる
- 写真を大量に残したい → R2 (10GB 無料だが、有効化にクレジットカード登録が必要)
- アプリ内で AI 分析を自動実行したい (WOD 写真の読み取りなど) → Anthropic API (1回数円)

## 主な技術

| 層 | 技術 | 理由 |
|---|---|---|
| 画面 | React 18 + TypeScript + Vite | 既存アプリと同じ。軽量な自作 SVG グラフ (依存を増やさない) |
| API | Hono (Workers 用の軽量フレームワーク) | 小さく速い。Workers の標準的な選択肢 |
| DB | D1 + 追加専用マイグレーション | SQLite 互換で、書き出し (SQL ダンプ) が容易 |
| 認証 | Cloudflare Access + `jose` で JWT 検証 + API トークン | 実績のあるライブラリで署名を検証 |
| 共通ロジック | `shared/` (項目定義・入力検証・分析) | 画面・API・CLI で同じ定義を使い、食い違いを防ぐ |
| テスト | Node 標準のテスト + ローカル Workers 環境での結合テスト | 追加の依存なし |
| CI/CD | GitHub Actions | テスト → バックアップ → マイグレーション → デプロイを毎回同じ手順で |

## 既存アプリとの関係

- **旧 CF MEMO** (GitHub Pages・データは各端末のブラウザ内) は、移行が終わるまでそのまま残す。データ書き出しボタンを追加済み
- **きょうトレ** (`/workout/`、誰でも使える公開サイト) は個人データを持たないので GitHub Pages のまま。今回の変更の影響は受けない
- 新プラットフォームは Cloudflare の別 URL。旧アプリの 12週プラン・WOD スキャンなどの機能は、ロードマップ (06) に沿って新プラットフォームへ移す
