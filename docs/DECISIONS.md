# 重要な決定事項 (新しいものを上に追記)

書き方: 日付 / 決めたこと / 理由 / 代わりに検討したもの

---

### 2026-11-18 アプリ名を VITALOG に変更
- 表示名・アイコンだけを変え、Worker 名 `cfm`・D1 名 `cf-memo`・リポジトリ名はそのまま (URL・データ・CI を壊さない)

### 2026-11-18 Apple Watch・体重計は Apple ヘルスケア経由で取り込む
- Web から HealthKit は読めず、iPhone の Safari は Web Bluetooth 非対応のため。体重計アプリ → ヘルスケア → (Health Auto Export かショートカット) → `/api/ingest/health`
- id を日付・開始時刻から決め、何度送っても二重登録しない。手入力の WOD と重なっても行は消さず、集計で手入力を優先

### 2026-11-18 WOD 写真の読み取りはサーバー側で Claude を呼ぶ
- API キーは Worker の Secret にだけ置く (旧アプリはブラウザに保存していた)。モデルは Claude Opus 5.5、effort low、構造化出力。拒否時はサーバー側フォールバックを有効化
- 読み取り結果は空欄だけを埋める (手で入れた内容は上書きしない)

### 2026-11-17 Claude Code の会話を「コーチ」、Web アプリを「記録と計算」に分ける
- アプリ内から AI API を呼ぶ機能は作らず、文章の分析・提案・レポートは Claude Code が DB を読んで行う
- 理由: 追加の API 料金がかからない。アプリ側は決まった計算 (推定1RM・トレンド・負荷比) だけにして、結果が再現できるようにする
- 検討: アプリ内で Claude API を呼ぶ (従量課金・キー管理が必要) → Phase 2 で WOD 写真読み取りだけ検討

### 2026-11-17 個人の健康情報は DB に置き、CLAUDE.md には置かない
- プロフィール・方針・目標は DB (`profile` / `goals` / `journal`)。CLAUDE.md は役割とルールだけ
- 理由: リポジトリが public。また記録は増え続けるので、ファイルではなく DB が正本であるべき
- `npm run cfm -- context` で毎回読み込む

### 2026-11-17 Cloudflare Workers + D1 + Access を採用
- 理由: 無料枠で長期運用でき、放置で停止しない。画面と API を1つの Worker で配信できて単純。Access でパスワードを自前管理しない
- 検討: Supabase (無料枠は1週間アクセスが無いと停止)、Cloudflare Pages (新機能は Workers 側に集約されつつある)

### 2026-11-17 データは「消さない」設計にする
- 論理削除のみ・すべての変更を audit_log に記録・マイグレーションは追加専用・取り込みはマージのみ
- 理由: 過去のアプリでデータが初期化された問題を二度と起こさないため。容量 (D1 5GB) に対して記録量は十分小さい

### 2026-11-17 旧 CF MEMO と きょうトレは GitHub Pages に残す
- 旧アプリはデータが端末のブラウザ内にあるため、書き出しが終わるまで消せない。きょうトレは公開サイトで個人データを持たない
- 移行完了後、private 化ときょうトレの移設を判断する
